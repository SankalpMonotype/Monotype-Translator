## Brand Voice

### Official Tone Sentiments (from Brand Guidelines v2.2)
The six approved brand sentiments, in order of emphasis:
1. **Simple**
2. **Empathetic**
3. **Humble**
4. **Confident**
5. **Approachable**
6. **Human**

### Core Voice Principles (direct from guidelines)
- **Keep it human.** The writing should feel human — close to conversational, but slightly
  elevated. Never talk down to readers; share expertise with empathy and humility. Reflect
  a shared understanding with creative and branding professionals.
- **Be a humble expert.** Keep it simple. Get to the point, but explain it in expressive,
  vivid, and succinct language. Have a bit of fun, but always offer something useful.
  Simply put, don't waste readers' time.
- **Create with passion.** The tone should reflect craft and creative energy.

### Tones to Avoid
- Casual / slang / colloquial (e.g. "Awesome!", "No worries!")
- Overly corporate or robotic (e.g. "The operation was successfully completed.")
- Condescending or jargon-heavy without context
- Alarmist error messages (frame problems as solvable, not catastrophic)

## Editorial Guidelines (AP Style, v2.2)

These rules apply to all written communications, internal and external, and must be observed
in translated copy where the target language allows.

### Sentence Case
- **All headlines, body copy, labels, and UI strings use sentence case** throughout all regions.
  This is a firm brand standard: "How to win the in-car technology race" — not "How To Win..."
- Translators must apply the equivalent sentence-case convention in each target language.

### Quotation Marks
- **Never use straight quotes** ( " or ' ). Use only typographic/curly/smart quotes.
  - English: "double" and 'single'
  - French: guillemets « » (with non-breaking space inside)
  - German: „lower-upper" quotation marks
  - Japanese: 「」for primary quotes
- This is explicitly stated in the guidelines: *"And never, ever, ever use straight quotes."*

### Style Reference
- Monotype adheres to the **Associated Press (AP) Stylebook** for all written content.

### Brand Name Formatting Rules
- **Compound brand names are always two distinct words** — never run together:
  - ✓ Monotype Fonts — ✗ MonotypeFonts
  - ✓ Monotype Cares — ✗ MonotypeCares
- **"Mono-" prefix is NEVER used.** All new products are "Monotype [Product]", never
  "Mono[Product]".
- Products follow the structure: **Monotype [Product name]** set in Helvetica Now MT Extra Bold.
- The official company name on first reference is **Monotype Imaging Inc.** Subsequent
  mentions may use "Monotype".

### Pull Quotes
- In articles and press releases, pull quotes must be attributed and distinctly marked.
- Italics for quotes only when styled via CSS; for non-quoted emphasis, italics are fine.

## Placeholder & Formatting Rules

### CRITICAL — Placeholder rules (two cases)

**Case 1 — Runtime variable tokens (identifier names): copy verbatim.**
These contain a code identifier (no spaces). Copy character-for-character into every translation.

| Format example          | Language           | Rule                                       |
|-------------------------|--------------------|--------------------------------------------|
| `{count}`               | All                | Copy verbatim; rearrange sentence around it |
| `{{company name}}`      | All                | Copy verbatim (double braces included)      |
| `{{division name}}`     | All                | Copy verbatim                              |
| `{{Monotype AI}}`       | All                | Copy verbatim                              |
| `{{user.count}}`        | All                | Copy verbatim                              |
| `%s`, `%d`, `%1$s`      | All                | Copy verbatim                              |
| `[name]`, `[DATE]`      | All                | Copy verbatim                              |

**Case 2 — Link-anchor label tokens (human-readable multi-word text in single braces): translate the label, preserve the braces.**
These are hyperlink anchors where the text inside is visible to the user and must be localised.

| English token    | French                       | German                  | pt-BR             | Japanese    | es-419           |
|------------------|------------------------------|-------------------------|-------------------|-------------|------------------|
| `{Terms of Use}` | `{Conditions d'utilisation}` | `{Nutzungsbedingungen}` | `{Termos de Uso}` | `{利用規約}` | `{Terms of Use}` |

Note: es-419 keeps `{Terms of Use}` in English (brand-approved).

**Example:**
- English: `{count} fonts available`
- French: `{count} polices disponibles` ✓
- French: `{nombre} polices disponibles` ✗ (variable renamed — WRONG)

**Japanese counter word rule (CRITICAL):**
When any count variable (`{{user.count}}` etc.) refers to users (ユーザー), always add the
counter 人: `{{user.count}} 人のユーザー`. Never omit 人.
- ✓ `{{user.count}} 人のユーザーを無効化しようとしています。`
- ✗ `{{user.count}} ユーザーを無効化しようとしています。`

### Preserve markdown and HTML formatting
- `**bold**`, `*italic*`, `` `code` `` — preserve as-is
- `<a href="...">`, `<strong>` — preserve tags verbatim; translate only visible text between tags
- URLs, email addresses, file extensions — do NOT translate

## Per-Language Localisation Guidelines

### French (fr-FR)
- Use formal **"vous"** (not "tu") throughout all UI and product copy.
- Avoid Anglicisms when a natural French equivalent exists.
  - Preferred: "télécharger" (not "uploader"), "police de caractères" (not "font" in formal contexts)
  - Exception: "font" is acceptable in casual UI labels where "police" would feel stilted.
- Apply French typographic rules: space before ":" and ";" (non-breaking), guillemets « » for quotes.
- Spell out "&" as "et" — do not use the ampersand symbol in French copy.
- Use "e-mail" (with hyphen), not "email".
- When addressing the user possessively, include the pronoun: "Entrez **votre** adresse e-mail".
- Confirmation dialogs: use "Êtes-vous sûr de **vouloir** désactiver…" (include "vouloir").
- UI strings: keep compact — French is typically 10-20% longer than English.
- Sentence case applies; French nouns are not capitalised by default.

### German (de-DE)
- Use formal **"Sie"** throughout. Never "du" in product UI.
- German strings are typically 20-40% longer than English. Prioritise clarity over brevity; avoid
  artificial truncation. Alert engineers to potential UI overflow.
- Compound words are normal and correct. Hyphenate compounds longer than ~20 characters for
  readability: "Schrift-Verwaltungs-Dashboard" over "Schriftverwaltungsdashboard".
- Technical English terms often remain in German tech contexts: "Download", "Upload", "Account",
  "Dashboard", "Label", "Foundry" are acceptable without translation.
- Keep "AI Search" partially localised as "KI-Suche" in German.
- Dialog strings use three distinct German forms based on context:
  (1) "You are about to X" → "Sie sind dabei, X zu [infinitive]." e.g. "Sie sind dabei, {{user.count}} Benutzer zu deaktivieren."
  (2) Confirmation question title e.g. "Deactivate X users?" → "Möchten Sie [Objekt] wirklich [Verb]?" e.g. "Möchten Sie {{user.count}} Benutzer wirklich deaktivieren?"
  (3) Affirmation button e.g. "Yes, deactivate X." → "Ja, [Objekt] [INFINITIV]." — object first, verb last. e.g. "Ja, {{user.count}} Benutzer deaktivieren." NEVER "Ja, deaktivieren Sie…"
- Sentence case: German capitalises ALL nouns — this is grammatically required and not a violation
  of the sentence-case rule.

## String Length Guidance

UI strings often have character or pixel limits. As a rule of thumb:

| Source language length | Expansion budget |
|------------------------|------------------|
| 1-10 chars             | +100% acceptable |
| 11-30 chars            | +50% acceptable  |
| 31-50 chars            | +30% acceptable  |
| 50+ chars              | +20% acceptable  |

If a translation significantly exceeds these budgets, note it with a reviewer_note and
suggest a shorter alternative.
